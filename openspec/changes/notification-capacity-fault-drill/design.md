# 设计

## 证据边界

本次容量入口使用现有 Nest Logger 输出 JSON，不新增 HTTP 路由或依赖。每批额外执行一次 `count`，统计所有 pending/processing（包括退避等待和活跃租约），它是非事务快照，不是“可立即认领数”。采样失败以 null 表示未知，继续原处理链路。耗时使用 `performance.now()` 单调时钟，逐尝试输出原始样本；p95/p99 由指定窗口的外部日志分析计算，不在进程中无限保存样本。增加的 count 和日志也会带来开销，真实压测需要计入。

任务结果以围栏条件更新是否成功为准；错误记录再次失败时标记 error，失去租约标记 lease_lost。关闭耗时只覆盖 onModuleDestroy 等待活动循环的区间，不等于 SIGTERM 到整个进程退出的时长。暂无单查询耗时、连接池占用或 Prometheus 指标。

先使用现有 PostgreSQL outbox 和 Jest fake Prisma 建立确定性场景，再在 Docker PostgreSQL 可用时补充集成验证。每个场景同时记录输入 backlog、处理耗时、数据库错误和最终任务状态，避免只看 HTTP 成功率。

## 故障场景

本次继续学习慢数据库对后台定时器的影响：setInterval 不会等待 async 回调，clearInterval 只取消未来调用。每个 processJob 保存一个在途心跳 Promise，未结束时跳过下个周期；finally 先清除定时器再等待该 Promise。心跳自身捕获查询错误，副作用前的主动续租仍是处理权检查。主动续租不属于周期心跳互斥范围；与终态更新并发的旧心跳仍由状态/令牌条件拒绝。测试通过 deferred Promise 控制数据库返回顺序，不靠真实 sleep，也不声称已演练操作系统暂停或 SIGKILL。

若数据库查询永久不返回，排空仍会等待；查询超时和部署强制终止属于后续边界，本次不引入应用内 Promise.race 来伪装数据库查询已取消。

- 数据库查询暂时失败：处理器捕获异常并延迟重试，不进入忙循环。
- 续租失败或事件循环暂停：旧实例失去处理权后不能覆盖新实例终态，任务可在租约过期后恢复。
- draining 后收到新调度：就绪探针返回 503，处理器不再认领新任务；当前任务按正常或强制终止路径分别记录。

## 注释约定

涉及批次、租约和终止顺序的常量或分支必须保留中文注释，说明三件事：它解决的故障、它依赖的测量假设、它不能推出的生产结论。注释应与 OpenSpec 场景同步，避免把演练数据写成永久保证。

## 验证边界

单元测试验证状态机和失败分支；集成测试验证 PostgreSQL 条件更新、租约恢复与幂等约束；E2E 只验证健康探针和停机期间的 HTTP 契约。真实容量仍需在部署环境中通过独立压测获得。
