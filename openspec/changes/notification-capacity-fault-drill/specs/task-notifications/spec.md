# task-notifications Specification

## ADDED Requirements

### Requirement: 续租心跳必须限制在途查询并在收尾时排空

同一任务的周期续租心跳 MUST 最多有一个查询在途。任务处理结束后 MUST 停止新的心跳，并等待已发出的心跳查询结束后才返回。单次心跳失败 MUST 被捕获；后续副作用前仍 MUST 用数据库条件更新确认租约有效，不得把心跳失败等同于立即获得或失去处理权。

#### Scenario: 慢查询跨过多个心跳周期

- **WHEN** 一个续租心跳查询尚未返回且下一个周期到达
- **THEN** 处理器不再发起第二个周期续租查询

#### Scenario: 任务结束时心跳仍在途

- **WHEN** 当前任务已经完成终态写入但心跳查询尚未返回
- **THEN** 任务处理与停机排空继续等待该查询
- **AND** 心跳结束后不再启动新的周期查询

#### Scenario: 一次心跳失败后租约仍有效

- **WHEN** 周期续租失败但副作用前的租约条件更新成功
- **THEN** 任务可以完成
- **AND** 心跳失败不会成为未处理 Promise rejection

### Requirement: 通知处理必须提供容量观测日志

处理器 MUST 在每批开始时采样所有租户的 `pending` 与 `processing` 总数作为未完成 backlog，并输出批次耗时、处理尝试数及循环是否异常退出。采样失败 MUST 标记为未知且不得阻止正常认领。每次处理尝试 MUST 输出耗时和 `completed`、`pending`、`failed`、`lease_lost` 或 `error` 结果，不得输出通知内容或租约令牌。关闭处理器 MUST 记录等待活动循环的耗时。

#### Scenario: 观测采样失败不阻断任务处理

- **WHEN** backlog 计数查询失败但任务认领查询可用
- **THEN** 处理器继续处理任务
- **AND** 批次日志的 backlog 为 null 而不是零

#### Scenario: 围栏拒绝过期实例的完成结果

- **WHEN** 通知写入后完成条件更新没有匹配当前租约
- **THEN** 尝试日志记录 lease_lost 而不是 completed

#### Scenario: 关闭时等待当前任务

- **WHEN** 处理器关闭且活动循环尚未完成
- **THEN** 关闭等待活动循环完成
- **AND** 输出单调时钟测得的等待耗时

### Requirement: 容量演练必须记录可解释证据

通知处理器的容量或故障演练 MUST 同时记录 backlog、任务处理耗时、数据库失败情况和最终任务状态；固定批次、租约时长和终止宽限期 MUST 被标记为待校准假设，而不是生产 SLO。

#### Scenario: 暂时数据库故障后恢复

- **WHEN** 通知处理器查询任务时数据库暂时不可用
- **THEN** 处理循环记录可诊断错误并延迟重试
- **AND** 不产生未处理 Promise rejection 或忙循环
- **AND** 数据库恢复后任务仍可按租约和幂等规则收敛

#### Scenario: 强制终止后的演练证据

- **WHEN** 进程在通知任务处理期间被强制终止
- **THEN** 演练记录任务当时的租约和处理阶段
- **AND** 后续实例可在租约过期后重新认领
- **AND** 重复通知仍由唯一约束和幂等写入收敛
